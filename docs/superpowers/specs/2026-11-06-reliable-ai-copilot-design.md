# Надёжный AI Copilot как основной режим Cyrano

Дата: 2026-11-06

## Статус

Утверждён и реализован. Текущий план: `docs/superpowers/plans/2026-11-06-reliable-ai-copilot.md`.

## Контекст и намерение

Cyrano сейчас совмещает телесуфлер и раннюю версию AI Copilot. Copilot должен стать основной возможностью приложения для защиты учебных проектов и технических собеседований, а телесуфлер должен остаться полностью рабочим вторичным режимом.

Основной сценарий Copilot: преподаватель говорит в Zoom, Teams, Meet или другом онлайн-звонке на Windows; приложение захватывает системный звук, локально распознаёт вопрос через Whisper, даёт пользователю короткое окно проверки и отправляет вопрос в подключённую LLM вместе с контекстом проекта. Когда ответ ссылается на реализацию, он показывает проверенный диапазон в формате `Filename.cs(150-170)`.

Текущая реализация нарушает этот сценарий в нескольких местах:

- Windows-пакет может содержать нативную зависимость `sharp` для macOS, поэтому `@huggingface/transformers` не загружается до начала скачивания Whisper.
- Ошибка loopback-захвата молча заменяется обычным микрофоном, но речь помечается как голос преподавателя.
- Ошибки STT теряются, а HUD продолжает выглядеть активным.
- Пустая расшифровка превращается в синтетический общий вопрос о проекте.
- Системный промпт содержит вымышленные примеры файлов и строк, которые модель может повторять как ответ.
- Аудиофрагменты обрабатываются конкурентно и могут быть молча отброшены при медленном Whisper.
- Поиск контекста выбирает первые совпавшие файлы и не проверяет ссылки из ответа.
- Настройка разбита между несколькими вкладками и не показывает общую готовность к занятию.

## Решения пользователя

- Главный сценарий: онлайн-звонок, особенно на Windows.
- Запуск ответа: гибридный. Вопрос определяется автоматически, показывается перед отправкой, его можно отменить или запустить сразу; ручная горячая клавиша остаётся.
- STT: локальный Whisper по умолчанию, отдельный облачный STT доступен как явная опция.
- Поддержка проектов: одинаковый общий путь для любых текстовых языков программирования; не делать C#-специфичный продукт.
- Ссылки: ответ должен прямо содержать проверенный формат `Filename.ext(start-end)`. Открытие IDE не является обязательной частью первой версии.
- UI: согласован линейный сценарий из экрана готовности и рабочего HUD.
- Продуктовая иерархия: Copilot основной, телесуфлер вторичный, но не урезанный.
- Технический подход: надёжный конвейер в существующем Electron/React-приложении, без полной переписи.

## Цели

1. На поддерживаемой Windows-сборке пользователь может скачать, проверить, загрузить и использовать локальную Whisper-модель.
2. Copilot честно показывает, слышит ли он системный звук, и никогда не подменяет источник без явного решения пользователя.
3. Ни тишина, ни ошибка STT, ни фраза пользователя с микрофона не запускают автоматический ответ от имени преподавателя.
4. Распознанный вопрос остаётся целым, виден перед отправкой и может быть отменён или исправлен.
5. Аудиофрагменты обрабатываются в порядке поступления и не теряются молча.
6. Ответ использует актуальный контекст выбранного проекта и не переносит историю или заметки из другого проекта.
7. Ссылка на код строится только из реально переданного модели фрагмента и проверяется по текущему файлу.
8. Перед запуском пользователь видит единый экран готовности: LLM, звук созвона, STT и проект.
9. Телесуфлер сохраняет существующие возможности и визуально входит в ту же навигацию.
10. Все пользовательские строки работают на русском, английском и украинском.

## Не-цели

- Не строить полноценную IDE, редактор кода или обязательную интеграцию с VS Code.
- Не гарантировать глубокий AST-анализ каждого существующего языка программирования.
- Не добавлять в первой версии отдельную векторную базу, локальную embedding-модель или набор Tree-sitter-грамматик.
- Не записывать и не сохранять исходное аудио занятия.
- Не переключать локальный STT на облачный автоматически.
- Не менять назначение классического телесуфлера и не удалять его настройки.
- Не обещать невидимость overlay во всех программах захвата без платформенного smoke-теста; существующая `setContentProtection(true)` сохраняется и проверяется отдельно.

## Анти-цели

Реализация считается неудачной, даже если формально отвечает, если выполняется хотя бы одно условие:

- HUD показывает «слушаю», когда модель или аудиозахват уже упали.
- Обычный микрофон молча выдаётся за системный звук.
- При пустом вопросе LLM получает общий или демонстрационный запрос.
- Модель может показать несуществующий файл или диапазон строк как проверенную ссылку.
- Переключение проекта оставляет заметки, индекс или историю предыдущего проекта.
- Ради Copilot ломаются прокрутка, горячие клавиши, геометрия или stealth-режим телесуфлера.
- Windows-релиз считается готовым только потому, что успешно собрался на macOS.

## Ограничения

- Сохраняются Electron 33, React 18, TypeScript, Vite и текущая IPC-модель.
- Overlay должен оставаться `alwaysOnTop`, защищённым от захвата и click-through вне интерактивных зон.
- На Windows системный звук берётся через Electron display-media handler с `audio: 'loopback'` и обычно относится к системному выходу по умолчанию.
- Chromium может потребовать пользовательский жест для начала `getDisplayMedia`; запуск нельзя оставлять фоновому `useEffect`.
- Локальный Whisper на Windows обычно работает на CPU, поэтому скорость зависит от ноутбука и размера модели.
- Любое «универсальное» понимание кода без языковых парсеров является гибридом структурных эвристик и LLM-анализа.
- В рабочем дереве уже есть незакоммиченные изменения упаковки Whisper, аудио и Windows overlay. Реализация должна интегрировать их, а не откатывать целиком.

## Рассмотренные подходы

### 1. Точечный ремонт

Исправить Windows native modules, loopback, ошибки STT, системный промпт и новый UI поверх текущих глобальных массивов, regex-детектора и файлового поиска.

Плюсы: минимальный diff и быстрый результат.

Минусы: конкурентные запросы, потеря аудио, слабый поиск и непроверенные ссылки остаются архитектурно возможными. Этот подход не отвечает требованию надёжности.

### 2. Надёжный конвейер в текущем стеке — выбран

Разделить capture, STT, review, answer и indexing на явные сервисы и состояния. Добавить последовательную очередь аудио, источник-зависимый триггер, универсальный индекс фрагментов и структурированные проверяемые ссылки. Перестроить настройки вокруг готовности.

Плюсы: устраняет корневые причины, сохраняет стек и телесуфлер, не добавляет тяжёлый поисковый runtime.

Минусы: затрагивает IPC-контракты, главный процесс, overlay, settings и тестовую инфраструктуру.

### 3. Tree-sitter, embeddings и векторный индекс

Добавить языковые грамматики, embedding-модель и semantic retrieval.

Плюсы: лучше масштабируется на очень большие репозитории и сложные семантические запросы.

Минусы: новые нативные зависимости, модели, размер приложения и ещё один источник Windows-сбоев. Для учебных репозиториев текущего масштаба это преждевременно.

## Целевой пользовательский поток

### Первый запуск и навигация

- Для новой установки `appMode` по умолчанию становится `copilot`.
- Существующее сохранённое значение `appMode` не перезаписывается.
- В боковой навигации первым идёт AI Copilot, затем Телесуфлер, затем общие настройки.
- Телесуфлер содержит существующий редактор текста, скорость, оформление, позицию и горячие клавиши.
- Copilot открывается на экране «Готовность к занятию».

### Экран готовности

Экран содержит четыре строки со статусом и локальным действием:

1. Модель ответа: провайдер, модель, URL, API key и реальная проверка непустого ответа.
2. Звук созвона: разрешение, наличие loopback-трека и живой уровень сигнала во время теста.
3. Распознавание: локальная модель или явно выбранный облачный STT, состояние загрузки и короткий тест речи.
4. Проект: папка, число проиндексированных файлов, время последнего индекса и состояние карты понятий.

Жёсткие блокеры запуска Copilot: нет рабочего LLM, нет выбранного/готового STT или не включён ни один разрешённый источник аудио. Отсутствие проекта показывает предупреждение и требует явного «Продолжить без проекта», но не блокирует общий Copilot.

Расширенные поля провайдера, промпта, модели, прозрачности и источников остаются доступны в отдельных разделах, но не перегружают экран готовности.

### Запуск системного звука

- Нажатие «Запустить Copilot» создаёт overlay в интерактивном стартовом состоянии.
- Если платформа требует transient user activation, overlay показывает одну крупную кнопку «Включить звук созвона» и временно является focusable/clickable.
- После успешного `getDisplayMedia` overlay возвращается в stealth/click-through режим.
- Если loopback недоступен или в треке нет сигнала, пользователь видит точную ошибку и действие «Повторить» или инструкцию проверить выход Zoom/Teams и системное устройство Windows.
- Приложение не открывает микрофон как fallback. Микрофон можно включить отдельно; он всегда остаётся источником `user`, а не `interlocutor`.

### Рабочий HUD

HUD показывает только текущий полезный контекст:

- Верхняя строка: реальный статус системного звука, STT, проекта и паузы.
- Блок вопроса: стабилизированный текст преподавателя и двухсекундное окно до автоответа.
- Действия: «Ответить сейчас», «Отменить», «Исправить текст» и глобальные горячие клавиши.
- Блок ответа: короткий произносимый ответ, детали и проверенные ссылки.
- Ошибка всегда заменяет ложный статус готовности и содержит конкретное действие восстановления.

После завершения ответа системный звук продолжает захватываться. Новый автоответ не запускается, пока предыдущий активен, но последующая речь может накапливаться как следующий вопрос. Очистка ответа не очищает проектный индекс.

## Состояния Copilot-сессии

Главный процесс владеет одной `CopilotSession`, а renderer получает снимки состояния. Минимальные состояния:

- `idle`: сессия не запущена.
- `awaiting-audio-permission`: нужен пользовательский жест или разрешение.
- `listening`: loopback активен, речь не обнаружена.
- `capturing`: обнаружена речь преподавателя.
- `transcribing`: один или несколько фрагментов находятся в очереди STT.
- `reviewing-question`: вопрос стабилизирован, идёт окно отмены.
- `answering`: LLM формирует ответ.
- `paused`: захват намеренно приостановлен.
- `error`: известная подсистема не готова; состояние содержит код, человекочитаемое сообщение и допустимые действия.

Каждая сессия получает `sessionId`; каждый вопрос получает `questionId`; каждый LLM-запрос получает `requestId`. Renderer игнорирует события неактивной сессии или запроса. История, pending-вопросы и ответы очищаются при смене проекта или завершении сессии.

## Аудиоконвейер

### Источники

- `system`: только подтверждённый loopback/display-media audio track. Только этот источник автоматически создаёт вопрос.
- `mic`: отдельный пользовательский микрофон. Он может добавлять разговорный контекст или использоваться для ручного вопроса, но не запускает автоматический ответ.
- Смешанного псевдоисточника нет. Если в будущем появится ambient fallback, он должен иметь отдельный тип и явное согласие пользователя.

Настройки источников соблюдаются буквально. Если оба выключены, приложение не вызывает `getUserMedia` и не запускает сессию.

### Захват и VAD

- Заменить deprecated `ScriptProcessorNode` на `AudioWorkletNode` с отдельным файлом worklet.
- Обрабатывать исходный sample rate устройства и ресемплировать в mono 16 kHz перед IPC.
- Использовать адаптивный noise floor, а не один глобальный RMS-порог.
- Хранить примерно 400–500 мс pre-roll, чтобы не обрезать начало слова.
- Завершать фразу после примерно 800–1000 мс устойчивой тишины.
- Не разрезать нормальный вопрос через шесть секунд. Предельный фрагмент — до 20 секунд; при вынужденном разбиении сохранять небольшой overlap и порядок.
- Слишком короткие, цифрово-тихие и повторяющиеся шумовые фрагменты отбрасывать до Whisper с диагностической причиной.
- Отслеживать `track.muted`, `track.readyState`, реальную энергию и время последнего сигнала.

Числа выше являются начальными инженерными значениями и выносятся в именованные константы, чтобы тестировать и калибровать их на фикстурах.

### Очередь STT

- Один `TranscriptionQueue` принимает фрагменты с монотонным sequence number и исходным временем начала/окончания.
- Локальный Whisper выполняет один inference за раз. Очередь не использует polling и не возвращает пустой результат по таймауту без события ошибки.
- Cloud STT может иметь отдельный ограниченный concurrency, но результаты всё равно собираются по sequence number.
- Backlog отображается как состояние «Распознавание отстаёт»; при достижении жёсткого лимита пользователь получает явную ошибку, а не тихую потерю.
- Timestamp расшифровки относится к времени аудио, а не к моменту завершения inference.

### Язык и качество

- Явные `ru`, `en`, `uk` фиксируют язык декодирования.
- `auto` не подменяется языком интерфейса. Реализация должна использовать реальный multilingual auto-detect поддерживаемого Whisper runtime и иметь фикстуры RU, EN и смешанной технической речи.
- Каталог объясняет компромисс скорость/точность. Base остаётся рекомендуемым минимумом для технических терминов; Tiny отмечается как быстрый режим.
- Локальный и облачный STT выбираются явно. Ошибка одного не переключает провайдера автоматически.

## Управление Whisper-моделями и Windows

### Разделение обязанностей

Создать отдельный `WhisperModelManager`; `WhisperService` только загружает полностью проверенную локальную модель и выполняет inference.

`WhisperModelManager` отвечает за:

- каталог и pinned revision каждой модели;
- полный manifest обязательных JSON/tokenizer/encoder/decoder файлов;
- обнаружение уже загруженных и bundled-моделей;
- загрузку во временный каталог;
- прогресс по байтам и текущему файлу;
- cancel/retry;
- проверку manifest и доступных checksum/размеров;
- атомарное перемещение готовой модели в cache;
- удаление или восстановление частичного cache.

Существующие пользовательские cache принимаются только после полной проверки manifest. Валидную старую модель повторно скачивать нельзя; неполную нужно восстановить.

Сетевые загрузки выполняются через Electron networking, чтобы учитывать системный proxy/TLS Windows. Mirror применяется только для классифицированной сетевой ошибки; ошибка native runtime или ONNX не маскируется второй сетевой попыткой.

Transformers запускается с локальным путём и запретом неожиданной remote-загрузки после того, как manager подтвердил готовность.

### Упаковка native modules

- Зафиксировать точные версии Transformers, ONNX Runtime и Sharp.
- Windows-релиз собирать на Windows x64 runner или из dependency tree, где явно установлены Windows optional packages.
- В `asarUnpack` включить `@img`, `sharp`, `onnxruntime-node`, `@huggingface` и необходимые runtime DLL.
- Исправить `pnpm-workspace.yaml`: native build approvals должны быть boolean, а поддерживаемые platform/arch — явными.
- Перед созданием installer запускать artifact audit, который проверяет Windows `sharp` package, `onnxruntime_binding.node`, DLL и manifest bundled-моделей.
- Добавить offline smoke: загрузить хотя бы одну полностью локальную модель и расшифровать короткую PCM/WAV-фикстуру без сети.
- Не прогревать и не скачивать Whisper при запуске телесуфлера или до выбора Copilot.

Bundled-модели допустимы и обнаруживаются manager, но продукт не должен считать неполный bundled-каталог готовой моделью.

## Определение и проверка вопроса

- Детектор работает только над завершёнными `system`-репликами.
- Соседние фрагменты объединяются только при одинаковом источнике, непрерывном времени и отсутствии уже отправленного вопроса.
- Regex-вопросительные слова остаются быстрым сигналом, но решение также учитывает вопросительный знак, императивы «покажите/объясните», длительность тишины и стабильность текста.
- Детектор не вызывает LLM напрямую. Он создаёт `QuestionCandidate` со статусом `pending`.
- HUD показывает текст и двухсекундный countdown. Отмена блокирует именно этот candidate. Ручной запуск отправляет его немедленно.
- Редактирование создаёт новую финальную версию candidate; исходная расшифровка остаётся только в памяти сессии.
- Если текста нет, пользователь получает «Вопрос не распознан». Общий архитектурный вопрос не подставляется.

## Индекс проекта

### Обход файлов

- Уважать `.gitignore` и стандартные generated/vendor/cache директории.
- Никогда не индексировать `.env*`, private keys, credential-файлы, бинарные и модельные файлы.
- Не ограничиваться первыми 48 KB файла: большой текстовый файл делится на line-aware chunks в допустимых пределах.
- Каждый файл хранит относительный POSIX-путь, hash, mtime, размер, язык/extension и массив line offsets.
- Индекс сохраняется локально в `userData` с версией schema и fingerprint корневой папки.
- Обновление инкрементально переиндексирует изменённые/новые/удалённые файлы.

### Универсальные фрагменты

Каждый `SourceChunk` содержит:

- стабильный `chunkId` внутри версии индекса;
- относительный путь;
- `startLine` и `endLine`;
- текст;
- имена/токены, найденные в пути и содержимом;
- language-neutral признаки: declaration-like строки, блоки, модификаторы доступа, циклы, условия, импорты, комментарии и вызовы;
- соседние chunk IDs для расширения контекста.

Эвристики не объявляются полноценным AST. Они дают одинаковый общий путь всем текстовым языкам и могут иметь дополнительные regex-адаптеры без изменения публичного контракта.

### Карта понятий

После выбора проекта подключённая LLM может построить компактную `ConceptMap` из уже созданных chunk IDs. В неё входят назначение проекта, архитектурные части и учебные понятия вроде инкапсуляции, наследования, циклов, валидации, хранения данных и API-потоков.

LLM не имеет права создавать путь или строки в карте: она выбирает только существующие chunk IDs. Неизвестные ID отбрасываются. Карта привязана к fingerprint индекса и инвалидируется после изменения соответствующих файлов.

Если AI-анализ ещё не завершён или недоступен, retrieval продолжает работать через file/path tokens, BM25-подобный lexical score, символы и language-neutral признаки.

### Retrieval

Для вопроса формируется набор кандидатов из:

- совпадений с ConceptMap;
- путей и символов;
- lexical/BM25 score по chunks;
- словаря общеучебных понятий и синтаксических сигналов;
- ограниченного контекста предыдущего ответа только внутри текущей сессии и fingerprint.

В prompt передаются лучшие фрагменты с непрозрачными source IDs, например `[S1]`, а не свободный список путей, который модель может продолжить выдуманным примером.

## LLM и проверяемые ссылки

### Prompt

- Удалить все вымышленные пути, классы и номера строк из default system prompt.
- Не отправлять запрос при пустом вопросе.
- Явно отделять инструкции, расшифровку, пользовательские заметки и недоверенный код проекта.
- Просить прямой произносимый ответ на языке вопроса.
- Разрешать ссылки только через переданные source IDs `[S1]`, `[S2]` и так далее.
- Если подходящего источника нет, модель должна сказать, что точное место не найдено, а не угадывать.

### Формат ответа

Потоковый текст может содержать source markers. Главный процесс разрешает markers через таблицу retrieval-кандидатов и формирует структурированный `Citation`:

```ts
interface Citation {
  id: string;
  relativePath: string;
  startLine: number;
  endLine: number;
  label: string;
}
```

`label` имеет вид `Filename.cs(150-170)`; при конфликте одинаковых basename используется относительный путь. Renderer получает текст и отдельный массив citations, а не повторно парсит произвольный Markdown.

Перед показом citation main process проверяет:

- source ID был передан этой модели в этом request;
- файл всё ещё находится внутри выбранного project root;
- диапазон положительный и не выходит за число строк;
- hash файла совпадает с индексом или chunk безопасно переиндексирован.

Неизвестная или устаревшая ссылка удаляется из проверенного списка. Текст ответа не должен визуально оформлять такую ссылку как подтверждённую.

### Провайдеры и запросы

- Сохраняются Anthropic и OpenAI-compatible transports.
- OpenAI-compatible parser корректно завершает последний buffer и поддерживает SSE, обычный JSON и распространённый NDJSON/Ollama формат.
- Пустой успешный HTTP-ответ считается ошибкой.
- Добавляются timeout, понятные provider errors и отмена по `requestId`.
- Новый request отменяет предыдущий, а renderer принимает события только активного request.
- Q&A history привязана к `sessionId` и project fingerprint.

## UI и визуальная система

Согласованный макет хранится во временной brainstorm-сессии; продуктовая реализация следует его структуре, но использует существующие tokens Cyrano:

- глубокие graphite/slate поверхности;
- чёткие 1px borders;
- синий только для действия;
- зелёный только для подтверждённой готовности/ссылки;
- amber для pending-вопроса;
- red для ошибки;
- Lucide icons вместо emoji;
- системный sans-serif и monospace только для путей/строк.

Настройки становятся resizable в разумных desktop-пределах и корректно работают с Windows scaling. Текст не должен быть меньше 12 px для основной информации. Все кнопки имеют visible focus, `aria-label`/`aria-pressed` по смыслу и локализованные названия. `prefers-reduced-motion` отключает декоративные переходы и typewriter-эффект.

HUD не показывает все горячие клавиши одновременно. Основные действия видны, остальные доступны через подсказки и настройки.

## Телесуфлер

Телесуфлер остаётся отдельным renderer-режимом в том же overlay и сохраняет:

- редактор текста и статистику;
- плавную прокрутку;
- скорость и rewind;
- шрифты, цвета, opacity, focal guide и mirror;
- размеры и position presets;
- global shortcuts;
- click-through, always-on-top и content protection.

Аудио, Whisper, индекс проекта и LLM не инициализируются в режиме телесуфлера. Общие настройки окна и локализации переиспользуются. Регрессионные тесты телесуфлера обязательны до готовности Copilot.

## IPC и данные

Текущие точечные IPC-вызовы заменяются/дополняются типизированными контрактами для:

- `getCopilotReadiness`;
- `startCopilotSession` / `stopCopilotSession`;
- `setCopilotPaused`;
- `confirmQuestion` / `cancelQuestion` / `editQuestion`;
- `getModelCatalog` / `downloadModel` / `cancelModelDownload` / `deleteModel`;
- `indexProject` / `refreshProjectIndex` / `analyzeProjectConcepts`;
- потоковых `CopilotSessionSnapshot`, model progress, index progress и answer events.

IPC handlers валидируют payload, model ID, provider URL, project path и session/request IDs. Renderer не получает произвольный filesystem API.

Новые settings получают schema version и default values. Миграция:

- сохраняет существующий `appMode`, текст телесуфлера, style, geometry и hotkeys;
- сохраняет провайдеры и ключи как есть в рамках этой задачи;
- проверяет существующую Whisper cache вместо повторной загрузки;
- очищает `contextCustomNotes` и Q&A history при смене project root;
- добавляет новые поля trigger countdown, source policy и model state без изменения старых файлов настроек вручную.

Перенос API keys в OS credential storage полезен, но не входит в эту переделку.

## Ошибки и диагностика

Ошибки имеют стабильный код подсистемы, например:

- `AUDIO_PERMISSION_DENIED`;
- `SYSTEM_AUDIO_NO_TRACK`;
- `SYSTEM_AUDIO_NO_SIGNAL`;
- `MODEL_INCOMPLETE`;
- `MODEL_NATIVE_RUNTIME_MISSING`;
- `STT_BACKLOG_LIMIT`;
- `LLM_UNAUTHORIZED`;
- `LLM_EMPTY_RESPONSE`;
- `PROJECT_INDEX_STALE`.

UI показывает понятное сообщение и действие. Технические детали пишутся в локальный rolling log без API keys, исходного аудио и полного текста приватных файлов. Экран готовности может копировать краткую диагностику для bug report.

## Тестирование

Добавить минимальную автоматическую test infrastructure, ориентированную на чистые функции и сервисы.

### Unit tests

- downsampling, adaptive VAD, pre-roll и endpointing на синтетических/коротких WAV fixtures;
- последовательность и backpressure `TranscriptionQueue`;
- silence/hallucination rejection;
- question candidates только из `system`;
- model manifest, partial download recovery и atomic completion;
- `.gitignore`/secret exclusions, line chunks, incremental reindex;
- retrieval для архитектуры, инкапсуляции, цикла и вызова функции на нескольких языках fixtures;
- citation validation и basename collision;
- settings migration и очистка project-scoped state;
- prompt не содержит fictional file examples и не создаётся без вопроса;
- SSE/JSON/NDJSON, final buffer, cancellation и empty response.

### Renderer tests

- readiness hard/soft blockers;
- pending countdown, cancel, edit и answer-now;
- stale `sessionId`/`requestId` events игнорируются;
- STT/model errors видны в HUD;
- локализация RU/EN/UK;
- Copilot-first navigation и полный путь к Teleprompter.

### Packaged smoke tests

- macOS: overlay lifecycle, audio cleanup, content protection call and teleprompter regression.
- Windows x64: native module audit, installer/portable start, user-gesture loopback, local model offline inference, system-audio signal and content protection.
- Linux: app start and teleprompter; Copilot system loopback поддерживается только если выбранный Electron/desktop path реально работает и отдельно отмечается в readiness.

Настоящий WASAPI loopback нельзя подтвердить на macOS. Финальная проверка Windows требует Windows runner или Windows-машину.

## Критерии приёмки

1. На чистой Windows x64 установке приложение запускается без ошибки Sharp/ONNX.
2. Загрузка выбранной модели показывает байтовый прогресс, переживает повтор после обрыва и завершается только при полном manifest.
3. После restart готовая модель определяется без сети; partial model не помечается готовой.
4. При недоступном loopback приложение не открывает микрофон и показывает восстановимое состояние ошибки.
5. Автоответ запускается только по расшифровке `system` после pending countdown.
6. При тишине, STT error или пустой расшифровке LLM-запрос отсутствует.
7. Длинный вопрос не обрезается каждые шесть секунд, а очередь не теряет фрагменты молча.
8. RU, EN и смешанная техническая речь проходят набор fixtures в режиме `auto` без принудительного языка UI.
9. Смена проекта очищает старые notes/history и меняет fingerprint индекса.
10. Ответ не может показать подтверждённую ссылку, которой не было среди retrieval-кандидатов.
11. Формат ссылки в UI соответствует `Filename.ext(start-end)` или относительному пути при конфликте имён.
12. Readiness screen однозначно показывает четыре подсистемы и блокирует запуск только по hard blocker.
13. Copilot открывается первым на новой установке; существующий пользователь не теряет выбранный Teleprompter mode.
14. Все текущие функции телесуфлера проходят регрессионную проверку.
15. `npm run typecheck`, production build, unit/renderer tests и package audit проходят.
